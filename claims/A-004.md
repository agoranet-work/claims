# A-004
**Claim:** From release v0.6.0, the Gravit Verifier applies the signed result of an evidence record: an admissible record signed false blocks a Verified Fact, and a record signed null is not counted as support.
**Author:** Gravit Open Network Foundation · 13 Oct 2026
**Command:** `git clone https://github.com/gravit-open-network-foundation/verifier && cd verifier && pip install -e . && python -m pytest` (47 golden vectors, Python and Rust); SAFR v1.1 reference adapter scenarios 9 and 10
**Code:** verifier v0.6.0, rule CANON-RES-012, seven new test vectors

**Finding (12 Oct 2026):** Iman Schrock, EMILIA Protocol, reported with a reproduction that release v0.5.0 ignored the signed result. In the SAFR v1.1 reference adapter, records signed true, false or null all produced a Verified Fact with identical decision IDs, and the repeat submission was disposed as Auto-Execute. Public demo keys; no payment was executed.

**Fix (13 Oct 2026):** verifier v0.6.0, rule CANON-RES-012, seven new test vectors.

**Scope:** this entry covers this one finding and its fix. It is not a review of the Gravit Verifier as a whole.
